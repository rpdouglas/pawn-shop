# Project E08: Click & Collect / Contact

**Status:** Done — 2026-05-18
**Epic:** E08 — Click & Collect / Contact
**Phase:** Phase 2 — Core Product
**Primary Persona:** Tanya — The Seasonal Celebrator
**Secondary Personas:** Sandra (≤3 taps from Pawn homepage), Makoonsii (contact page accessibility), Staff (reservation inbox)
**AI Involvement:** Claude (dev) only — no Gemini runtime involvement

**Objective:** Deliver a click-and-collect reservation flow on Pawn and Fireworks item detail pages, backed by a Cloud Function that dispatches an SMS acknowledgment within 60 seconds of creation, a staff reservation inbox to confirm or decline pickup windows, an admin-configurable store hours system that generates 30-minute pickup slot intervals, and a contact page with a Google Maps embed and email-routing contact form.

---

## 1. User Story

> As **Tanya**, I want to reserve fireworks items and receive an SMS confirmation with a specific pickup window so that I know exactly when to arrive and do not have to worry about the stock being gone.

> As **Makoonsii**, I want to find the store's address and contact information on a simple, accessible page so that I can reach the staff without friction.

## 4. Schema & Architecture

### Firestore Collections Impacted

```
Collection: items/{id}
Fields read: title, price, condition, status, viewTag, policeHold, images
Fields written: status → 'reserved' (set by confirmReservation CF, not by customer)

Collection: reservations/{id}
Fields read: uid, itemId, status, pickupWindow, staffNotes, createdAt
Fields written: all fields on create; status + pickupWindow + staffNotes on staff update

Collection: config/storeHours (single document)
Fields read: monday–sunday maps, updatedAt (read by ClickCollectModal + createReservation CF)
Fields written: monday–sunday maps, updatedBy, updatedAt (admin only via updateStoreHours CF)
```

### Slot Generation Logic

Slots are computed client-side in `ClickCollectModal` from `config/storeHours`:
- Customer first selects a date (today + up to 13 days, i.e. a 2-week booking window)
- For the selected date's day-of-week, read `open` and `close` from the hours document
- If `closed: true` for that day, display "Store closed — choose another date"
- Generate slots from `open` to `close − 30 minutes` in 30-minute intervals
  - e.g., open 09:00 / close 17:00 → slots 09:00, 09:30, …, 16:30
- For today's date, filter out any slots where the slot time has already passed (local time)
- Customer selects one slot → stored as `pickupWindow: "YYYY-MM-DD HH:MM–HH:MM"` (e.g. `"2026-07-01 14:00–14:30"`)

Server-side validation: `createReservation` CF re-reads `config/storeHours` and validates the submitted `pickupWindow` is a legitimate slot for that day before creating the document. Rejects invalid slots with a descriptive error.

### Phase 2 — Cloud Functions

**`createReservation` (callable)**
- Trigger: callable — authenticated customer
- Auth check: `request.auth` must be present
- Steps: (1) validate itemId exists, status == 'active', policeHold != true; (2) read `config/storeHours` and validate the submitted `pickupWindow` is a legitimate 30-minute slot for that day (reject with descriptive error if not); (3) create `reservations/{id}` with status: 'pending'; (4) dispatch Twilio SMS to `customerPhone` within the function execution (no Firestore trigger — inline for 60-second SLA); (5) set `smsDeliveredAt` timestamp; (6) write `auditLogs` entry `reservation_created`; (7) return `reservationId` to client
- SMS body: `"The Pawn Shop — your collection request has been received. Requested window: [pickupWindow]. We'll confirm shortly."` — no item category words
- Error handling: if Twilio fails, reservation is still created; `smsDeliveredAt` remains null; `staffNotes` auto-set to "SMS failed on create — resend manually"

**`confirmReservation` (callable)**
- Trigger: callable — staff only (admin/manager/inventory_staff)
- Auth check: custom claims `admin | manager | inventory_staff`
- Steps: (1) update `reservations/{id}.status` to 'confirmed' or 'declined'; (2) if confirmed: set `pickupWindow` (staff-provided specific slot), update `items/{id}.status` to 'reserved'; (3) dispatch confirmation SMS to `customerPhone`; (4) write `auditLogs` entry `reservation_confirmed` or `reservation_declined`
- Confirmed SMS body: `"The Pawn Shop — your collection is confirmed. Pickup: [pickupWindow]. See you then."` — no category words
- Declined SMS body: `"The Pawn Shop — unfortunately we can't fulfill your collection request. Please contact us to discuss alternatives."`

**`sendContactEmail` (callable)**
- Trigger: callable — unauthenticated allowed (contact form is public)
- Auth check: none (rate-limited by Firebase App Check or basic throttle)
- Steps: (1) validate inputs (name, email, message — server-side); (2) send email via SendGrid to staff inbox address (stored in CF env, not in Firestore); (3) no Firestore persistence — transactional email only; (4) no `auditLogs` entry (no PII can go in logs; contact form is PII-only)
- No collection created — message is not persisted to Firestore

**`completeReservation` (callable)**
- Trigger: callable — staff only
- Steps: (1) update `reservations/{id}.status` to 'completed'; (2) update `items/{id}.status` to 'sold'; (3) write `auditLogs` entry `reservation_completed`

**`updateStoreHours` (callable)**
- Trigger: callable — admin only
- Auth check: custom claim `admin` required (manager and inventory_staff cannot modify hours)
- Steps: (1) validate all seven day maps have valid `open`/`close` HH:MM strings and `closed` boolean; (2) validate open < close for each non-closed day; (3) write `config/storeHours` (merge); (4) set `updatedBy` = caller UID, `updatedAt` = server timestamp; (5) write `auditLogs` entry `store_hours_updated` with `details: { daysModified: string[] }` — no PII
