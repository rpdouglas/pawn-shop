## 3. Compliance Gate

- [x] **Age gate required?** Yes — fireworks 18+, enforced at router level (`/fireworks` route). Pre-order form additionally checks `ageVerified` session state before rendering. Age gate pass/fail already logged to `auditLogs` via `logAgeGate` CF (E05).
- [x] **`auditLogs` events defined?** Yes — `campaign_activated`, `campaign_deactivated`, `preorder_created`, `preorder_confirmed`, `preorder_ready`, `preorder_collected`, `preorder_cancelled` (added to schema 2026-05-18).
- [x] **PII excluded from all logs?** `auditLogs.details` for preorder events uses `{preorderId, viewTag}` — no name, phone, or email. PII stays in `preorders/{id}` only.
- [x] **`policeHold` logic respected?** Preorders only reference `items/{id}` — if a preorder item gains `policeHold: true`, staff must cancel the preorder manually. No automated pre-order cancellation on `policeHold` for MVP (staff alert only).
- [x] **`aiDescription` separation maintained?** Not touched in this epic.
- [x] **AI API calls via Cloud Functions?** No AI API calls in E14.

## 5. Implementation Phases

### Phase 1 — Cloud Functions

- [ ] `activateCampaigns` (scheduled, every 5 min): query `campaigns` where `startDate <= now && active == false && endDate >= now`; set `active: true`, `updatedAt: now`; write `campaign_activated` auditLog
- [ ] `deactivateCampaigns` (scheduled, co-located): query `campaigns` where `endDate < now && active == true`; set `active: false`, `updatedAt: now`; write `campaign_deactivated` auditLog
- [ ] `createPreorder` (callable): validates 18+ session (custom claim or session cookie approach), writes `preorders/{id}` with all required fields, writes `preorder_created` auditLog, does NOT send SMS (pending staff confirmation)
- [ ] `confirmPreorder` (callable, staff only): transitions status → `confirmed`, fires Twilio SMS within CF execution window, sets `smsDeliveredAt`, writes `preorder_confirmed` auditLog
- [ ] `markPreorderReady` (callable, staff only): transitions status → `ready` + sets `pickupWindow`, fires SMS with specific pickup window, writes `preorder_ready` auditLog
- [ ] `collectPreorder` (callable, staff only): transitions status → `collected`, writes `preorder_collected` auditLog
- [ ] `cancelPreorder` (callable, staff or customer): transitions status → `cancelled`, writes `preorder_cancelled` auditLog

### Phase 2 — Frontend Components

- [ ] Wire `CountdownTimer` in `FireworksPage.tsx` to query active campaign with `countdownEnabled: true` — remove hardcoded Canada Day fallback
- [ ] `CampaignBanner` component — reads `bannerCopy` + `discountRule` from active campaign; renders on PawnPage / CannabisPage / FireworksPage based on `viewTag`
- [ ] `PreorderForm` component — fireworks-only, shown only after age gate pass, calls `createPreorder` CF
- [ ] Staff pre-order inbox page or tab — lists preorders by status, staff confirm/ready/collect actions

### Phase 3 — Admin Campaign UI

- [ ] Campaign create/edit form in admin area: title, viewTag, startDate, endDate, bannerCopy (160 char limit + counter), discountRule, countdownEnabled toggle
- [ ] Campaign list view showing active/upcoming/expired campaigns

### Phase 4 — QA

- [ ] Tanya: pre-order form blocked without 18+ age gate pass
- [ ] Tanya: SMS confirmation arrives within 60s of confirm action
- [ ] Makoonsii: banner copy passes brand voice check — no prohibited vocabulary
- [ ] Marie: cannabis campaign SMS does not disclose category
- [ ] Compliance: auditLogs events firing correctly for all preorder transitions
