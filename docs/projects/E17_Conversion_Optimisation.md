# Project E17: Conversion Optimisation

**Status:** Active — 2026-05-18
**Epic:** E17 — Conversion Optimisation
**Phase:** Phase 4 — Conversion & Admin Intelligence
**Primary Persona:** Sandra (visual discovery, live activity)
**Secondary Personas:** Dale (recently sold validates deal quality), Makoonsii (years-in-business trust), Kevin (hold countdown), Marcus (authentic scarcity display)
**AI Involvement:** Claude (dev) only

**Objective:** Deliver five trust and conversion signals on the public storefronts: a recently sold strip (real sold data only), a years-in-business badge with testimonials, a privacy-safe live activity feed (city-level, rate-limited, no PII), `limited-edition`/`rare-find` badge display (staff-set only, never manufactured), and a hold countdown badge on reserved items.

---

## 1. User Story

> As **a storefront visitor (Sandra)**, I want to see genuine social proof — what sold recently, how long the shop has been here, and that others are browsing right now — so that I feel confident the inventory is real and the store is active.

---

## 2. Persona Acceptance Criteria

### Primary Persona Gate — Sandra

> Live activity feed must show no PII, no real names, no item-level precision. "Someone in Cornwall Island is browsing Pawn" is the ceiling of specificity.

- [ ] Activity feed displays city-level action only — never customer name, UID, or item ID
- [ ] Activity feed is rate-limited server-side — no more than one feed entry per viewTag per 30 seconds
- [ ] Activity feed entries auto-expire (purged after 24 hours)
- [ ] Recently sold strip shows real sold items only — `soldAt` timestamp set by CF, never manufactured

### Makoonsii Trust Test

- [ ] Years-in-business badge uses community-rooted copy ("X years serving Akwesasne") — not generic retail language
- [ ] Testimonials (if staff-written) use warm, plain language — Flesch-Kincaid Grade 8 or lower
- [ ] No Kanien'kéha text generated by AI — community review required before any publication

### Marcus Scarcity Integrity Test

- [ ] `limited-edition` and `rare-find` badges only render when those tags exist in `items/{id}.merchandisingTags[]`
- [ ] No algorithmic inference of scarcity — only staff-written tags via `updateMerchandisingTags` CF
- [ ] MerchandisingBadge renders on masonry grid cards and ItemQuickView — existing E13 component reused

### Dale Verification Test

- [ ] Recently sold strip items link through to the item or show the sold price — validates deal quality
- [ ] `soldAt` is set by the CF that transitions status to `'sold'` — not derived from `updatedAt`

### Kevin Speed Test

- [ ] Hold countdown badge visible on reserved items (`status='reserved'`) displaying `holdExpiresAt - now`
- [ ] Badge updates every 60 seconds — no second-by-second digit flip (prohibited on Pawn view)
- [ ] Badge disappears when `holdExpiresAt` passes

## 3. Compliance Gate

- [ ] **Age gate required?** No — all E17 components are public-facing overlays on existing gated pages
- [ ] **`auditLogs` events required?** No — no staff write actions in this epic
- [ ] **PII exclusion** — `activityFeed` entries must never include: UID, name, email, phone, IP address, device ID, precise location. City string is hardcoded `"Cornwall Island"` — not derived from user data.
- [ ] **`policeHold` respected** — recently sold strip must exclude items where `policeHold: true`. Same for activity feed — `logActivity` CF must verify item is not police-held before writing.
- [ ] **`aiDescription` draft-only** — not touched in this epic
- [ ] **Scarcity integrity** — `limited-edition` / `rare-find` display reads only from `merchandisingTags[]`. Component must not infer scarcity from `viewCount`, `enquiryCount`, or any computed field.
- [ ] **Motion compliance** — hold countdown badge: text update every 60s, no digit flip animation on Pawn view. Activity feed: fade-in on new entry only (slow fade, 400ms). No constant micro-animation.

## 4. Schema & Architecture

### Schema Additions Required Before Implementation

All fields below must be added to `docs/firestore-schema.md` before any code is written.

#### `items/{id}` — new field

| Field | Type | Notes |
|-------|------|-------|
| `soldAt` | timestamp | Set by `completeReservation` and `ebayWebhook` CFs when status transitions to `'sold'`. Null until sold. |

#### `config/shopInfo` — new single document (Strategy B+)

| Field | Type | Notes |
|-------|------|-------|
| `foundedYear` | number | e.g. `2010`. Used to compute years-in-business badge. Admin-only write. |
| `ownerName` | string | Optional. Used in testimonials display. |
| `updatedBy` | string | UID of admin who last modified |
| `updatedAt` | timestamp | Server timestamp |

#### `activityFeed/{id}` — new collection (Strategy B+)

| Field | Type | Notes |
|-------|------|-------|
| `viewTag` | string | `pawn` \| `cannabis` \| `fireworks` |
| `action` | string | `'browsing'` — only value for MVP |
| `displayCity` | string | Hardcoded `"Cornwall Island"` — never derived from user data |
| `createdAt` | timestamp | Server timestamp. Used for ordering and TTL purge (>24h). |

> **Privacy guarantee:** `activityFeed` contains no UID, no item ID, no IP, no customer-traceable data. The only personal element is `viewTag` which maps to a public storefront, not a customer.

### Firestore Queries

```
// Recently sold strip
items where status='sold' orderBy soldAt desc limit 5

// Live activity feed
activityFeed orderBy createdAt desc limit 10

// Hold countdown badge
items/{id}.holdExpiresAt (read at item load — no separate query)

// Merch badges
items/{id}.merchandisingTags (read at item load — no separate query)
```

### Cloud Functions Required

| CF | Trigger | Purpose |
|---|---|---|
| `logActivity` | Callable | Writes city-level activity entry. Rate-limited: skips write if same viewTag written < 30s ago. |
| `completeReservation` (update) | — | Add `soldAt: FieldValue.serverTimestamp()` on status→sold |
| `ebayWebhook` (update) | — | Add `soldAt: FieldValue.serverTimestamp()` on eBay sync-sold |

### New Components

| Component | Route / Placement | Notes |
|---|---|---|
| `RecentlySoldStrip` | `PawnPage` (below hero) | Horizontal scroll, max 5 items, real soldAt only |
| `YearsInBusinessBadge` | `PawnPage` hero section | Reads `config/shopInfo.foundedYear`, computes `currentYear - foundedYear` |
| `TestimonialsModule` | `PawnPage` (below sold strip) | 2-3 static staff-written quotes (Strategy B) or `testimonials/{id}` (Strategy C) |
| `ActivityFeed` | `PawnPage` sidebar / bottom strip | onSnapshot, city-level only, rate-limited |
| `HoldCountdownBadge` | `ItemQuickView`, `MasonryCard` | Reads `holdExpiresAt`, updates every 60s |
